## Known limitations

- **The reference scene is not static.** Sampling camera position and a hand mesh's world position at increasing delays after load shows the camera flies in and settles by ~2s, while the arm keeps moving even at 8s (a looping idle animation) -- there is no single "rest pose". Every phase 1-3 extraction implicitly captured whatever moment its `waitForTimeout(300)` landed on, close to the scene's t=0 authored base state. This script uses that same ~300ms timing so the comparison is apples-to-apples with what's actually baked into `build-scene.js`, rather than "pixel-perfect against the live reference," which isn't a coherent goal when the reference keeps moving. Animation fidelity is phase 5's territory (not attempted here).
- **No multi-angle comparison.** Originally proposed in phase 3's plan, but the reference app's camera can't be moved by script -- Spline's render loop overrides it every frame regardless of `_frameView.enableResponsive` or direct `position`/`lookAt` calls. Only the single default camera angle is compared.
- **Pixel diff includes known, already-flagged gaps** (materials ledger in `docs/phase2-materials-ledger.md`, shape-helper approximations in `shape-helpers.js`) -- it is not a fidelity score to drive toward zero, it's a baseline to catch new regressions.
